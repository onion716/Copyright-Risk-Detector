# 规则审查：小红书虚拟商品的「售假」判定

- 审查日期：2026-11-08
- 审查对象：`assets/banned-words.json`（v1.0）、`assets/platform-rules.json`、`assets/handling.json`、`index.js` 中的 `scoreHits` / `SYSTEM_PROMPT`
- 参考材料：
  - [《【更新5W+字】小红书虚拟产品从0到1实操手册》](https://my.feishu.cn/wiki/ZhzJwSnlTitB5Qk1XPHc2MWGnCg)
  - [《10月AI虚拟产品训练营（Pro版）· 所有学习资料整理》](https://my.feishu.cn/wiki/OPgJwAb0ViKK09kvMSlc4Tj1nMg)
  - 用户反馈截图：商品为「对海外文章的个人解读知识库」，本地检测命中「秒发 / 网盘链接 / 自动发货」，被判「售假与侵权暗示」、红灯、风险分 55。

---

## 一、结论

这次误判不是单个词的问题，而是**整个「售假」词组的判定口径错位**：

> 现行 `counterfeit` 组把「交付方式」「商品形态」「营销描述」「软件破解」「账号会员禁售」和「真正的售假/假冒」混在同一个红色分组里，再用「命中即红灯」的方式打分。

其中「秒发 / 自动发货 / 网盘链接 / 网盘发货 / 电子版 / PDF 版」等，是小红书虚拟商品**官方支持的正常交付方式**；「全套 / 全集 / 最新版 / 原价」只是普通商品描述；把它们判成「售假高频词」，会把整个知识库、模板、PPT、课件类目误伤。

根因：这套词表是从**闲鱼（二手交易平台）**的「售假与版权高频词」直接沿用的。闲鱼上「网盘秒发」经常是盗版资源卖家的特征；小红书是内容电商，官方已有「电子资源」类目与自动发货功能，同一个词在两边的语义完全不同。

---

## 二、两篇文档里的关键平台口径

### 1. 小红书官方支持虚拟产品与自动发货

《小红书虚拟产品从0到1实操手册》第 11 问明确写到：

> 小红书发货没有标准答案，可以通过分享网盘链接、飞书文档链接，或者通过邮箱进行发货。
>
> 同时小红书官方已经发布关于虚拟产品新规，官方支持虚拟产品出单后自动发货啦，主要操作步骤如下：
> 1/ 店铺管理 - 类目管理 - 新增类目中，增加【电子资源】类目；
> 2/ 把已经上架的虚拟产品【编辑】，更改类目为【电子资源】，商品规格那就可以填写发货链接和发货说明了；
> 3/ 发货后客服后台也会自动推送链接。

### 2. 个人售卖是平台认可的承接方式

《10月AI虚拟产品训练营（Pro版）》「第三天 · 确定你的销售承接方式」给出三种路径：

| 路径 | 门槛 | 说明 |
|---|---|---|
| 小红书店铺 | 保证金约 1000 元；电子资源类目准入 | 虚拟资料、模板、课件教辅属于定向准入白名单类目，需完成官方「电子资源」类目报白后才能合规上架并使用自动发货；个人店凭身份证即可开店 |
| 个人售卖 | 门槛较低，实名后即可申请 | 适合起步阶段先验证需求与转化，不必先押保证金 |
| 引流到私域 | 无平台开店要求 | 适合产品线较长、做复购和服务的情况 |

文档同时把「知识库、PPT 模板、课件教案、电子资料包、设计素材、图集」等列为正常的虚拟产品类目。

### 3. 文档里的「侵权」讨论也不等于「售假」

手册 FAQ 第 3、7、23 问讨论的是「知识库含品牌方方案/报告是否侵权」，建议是：**做二次创作、注明公开来源、或走正版授权/会员**。这说明平台侧真正关注的是**内容来源与授权**，不是「有没有用网盘交付」。

## 三、用户反馈案例复盘

输入（大意）：

> 商品：对海外文章的个人解读知识库
> 详情：拍下秒发，网盘链接自动发货，电子版 PDF 可直接阅读

旧规则命中：

| 片段 | 旧判定 | 旧建议 |
|---|---|---|
| 秒发 | 售假与侵权暗示（红） | 自动发货文件是售假高频特征 |
| 网盘链接 | 售假与侵权暗示（红） | 去掉对原作品、账号或品牌的指向，改成描述你自己交付的内容 |
| 自动发货 | 售假与侵权暗示（红） | 同上 |

结果：版权 0 条、违禁/极限词 3 条，**触发原因「售假高频词」→ 红灯 → 风险分 55**。

这条商品是卖家自己「对海外文章的个人解读知识库」，属于文档中明确支持的**内容策展型虚拟产品**；「秒发 / 网盘链接 / 自动发货」只是交付说明。旧规则把正常经营行为判成售假，属于**规则性误伤**。

## 四、问题清单

### 问题 1：场景错配（闲鱼词表套到小红书）

`banned-words.json` 的 `counterfeit` 组（47 个词）与 `xianyu-blacklist/assets/banned-terms.json` 的 `fake` 组逐字一致。闲鱼是二手交易平台，虚拟资源交易本身受限；小红书是内容电商，官方支持虚拟产品和个人售卖。直接复用会造成系统性误伤。

### 问题 2：交付方式被当成售假特征

错误词条：`秒发`、`自动发货`、`网盘链接`、`网盘发货`、`网盘打包`、`百度云`、`夸克网盘`、`阿里云盘`、`拍下发链接`。

这些是**交付时效与交付渠道**，不是商品真伪。小红书官方自动发货就是让商家填写「发货链接」和「发货说明」。

### 问题 3：商品形态被当成侵权复制

错误词条：`电子版`、`PDF版`。虚拟商品本来就是电子文件；「电子版/PDF 版」是格式说明。

`扫描版`、`录屏`、`录播课`、`无水印` 需要看上下文：自制内容可以正常卖，只有复制他人作品才侵权，应该降为「黄灯提示核对授权」，不能直接红灯。

### 问题 4：营销描述被当成售假

错误词条：`全套`、`全集`、`最新版`、`原价`、`永久更新`、`包更新`、`包更`、`免费领`、`白嫖`。

这些是营销/描述用词，最多涉及广告法或平台夸大宣传，不应归入「售假」。

### 问题 5：不同违规类型混在一个红色分组

`破解`、`破解版`、`激活码`、`注册机`、`序列号` 属于**软件破解/盗版**；`代充`、`代付`、`合租`、`拼车`、`共享账号`、`账号共享` 属于**账号与会员类禁售**。它们确实高危，但**不是售假**。混在 `counterfeit` 组里会让用户看到「售假」这个错误标签，也会让模型把问题理解错。

### 问题 6：命中即红灯，缺少上下文与分级

旧逻辑 `scoreHits` 对任何 `level: red` 的违禁词直接判红，没有考虑：
- 同一个词在「自有原创」与「搬运他人作品」语境下含义不同；
- 交付方式词不应参与风险打分；
- 三个正常交付词叠加不应该累加成「售假」。

### 问题 7：代码把原因硬编码为「售假高频词」

`index.js` 旧代码：

```js
if (h.level === 'red') { level = 'red'; reasons.push('售假高频词') }
```

任何红色违禁词组（包括未来的破解、账号、医疗等）都会被显示成「售假高频词」。应改为使用分组名，例如「破解 / 账号会员类禁售」「售假 / 假冒正品」。

### 问题 8：DeepSeek 复核没有平台例外口径

旧 `SYSTEM_PROMPT` 只说要查「售假与侵权」，没说小红书支持自动发货/网盘交付。即使本地词库改对了，模型仍可能凭「网盘链接」给红灯。因此必须把平台口径写进提示词。

### 问题 9：平台规则卡片信息过时

旧 `platform-rules.json` 的 `xhs_category` 只写「知识库等虚拟产品曾集中下架，没有合适类目承载」「可用个人售卖降低风险」，没有写：
- 官方「电子资源」类目；
- 自动发货流程；
- 个人售卖适合起步、不等于违规。

### 问题 10：UI 文案与示例强化了错误印象

- 商品名称输入框占位符是「例如：粉笔公考全套网盘秒发」——直接把「网盘秒发」当作默认示例，暗示这是风险写法；
- 「打分说明」写「售假高频词 → 红」，没有解释正常交付方式不扣分。

## 五、词条重分类

### 5.1 新分组

| 分组 | 名称 | 等级 | 是否扫描 | 说明 |
|---|---|---|---|---|
| `counterfeit` | 售假 / 假冒正品 | 红 | 是 | 只保留真正的假冒、盗版、翻录、官方同款等 |
| `piracy` | 侵权复制暗示（需核授权） | 黄 | 是 | 内部资料、录屏、录播课、去水印、扫描版等，需结合来源判断 |
| `license` | 破解 / 账号会员类禁售 | 红 | 是 | 破解、激活码、注册机、代充、共享账号等平台禁售项 |
| `marketing` | 夸大 / 不实描述 | 黄 | 是 | 全套、全集、最新版、原价、永久更新等营销词 |
| `absolute` | 绝对化 / 极限用语 | 黄 | 是 | 广告法极限词，保持原样 |
| `platform` | 平台稽查高频词 | 黄 | 是 | 影视、代写、教培等平台敏感词 |
| `delivery` | 正常交付方式 / 商品形态（不参与风险判定） | 绿 | **否** | 秒发、自动发货、网盘链接、电子版、PDF 版、发货链接、飞书文档、邮箱发货等 |

### 5.2 具体迁移

**从售假组移出（不再判风险）**

`秒发`、`自动发货`、`网盘链接`、`网盘发货`、`网盘打包`、`百度云`、`夸克网盘`、`阿里云盘`、`拍下发链接`、`电子版`、`PDF版`、`原版`（「英文原版 PDF」等正常用法）。

**移入正常交付/商品形态组（不扫描）**

另补充：`发货链接`、`飞书文档`、`邮箱发货`、`网盘`、`网课课件`、`真题题库`、`可打印`、`MP3`、`图集`。

**移入营销描述组（黄灯）**

`全套`、`全集`、`最新版`、`官方正版`、`原价`、`永久更新`、`包更新`、`包更`、`免费领`、`白嫖`、`随机送`。

**移入侵权复制暗示组（黄灯）**

`原课`、`内部资料`、`内部课`、`内部讲义`、`无水印`、`去水印`、`高清无水印`、`录屏`、`录播课`、`同款资料`、`扫描版`、`盗录`。

**移入破解/账号会员禁售组（红灯）**

`破解`、`破解版`、`激活码`、`注册机`、`序列号`、`代充`、`代付`、`合租`、`拼车`、`共享账号`、`账号共享`、`免STEAM`、`外挂`、`绿色版`。

**保留在售假/假冒组（红灯）**

`官方同款`、`假冒`、`高仿`、`复刻版`、`盗版`、`翻录`。

## 六、代码与文案调整

1. `index.js` `buildIndexes`：过滤 `group.scan === false` 的词条，正常交付组不进入扫描索引。
2. `index.js` `scoreHits`：红色违禁词的原因改用分组名，不再硬编码「售假高频词」。
3. `index.js` 新增 `adviseBannedHits`：当违禁词是主要风险来源时，生成对应的处置卡，不再显示「本地名单未收录」。
4. `index.js` `SYSTEM_PROMPT`：增加「重要平台口径」段落，禁止仅凭自动发货/网盘/电子版等词判售假。
5. `assets/platform-rules.json`：更新 `xhs_category`，新增 `xhs_virtual_delivery` 正常交付规则类别。
6. `assets/handling.json`：改写「售假记录」标签的含义与动作，强调自有原创商品正常交付不受影响；精确命中基础分 55 → 65，修复「本地红灯、处置卡却黄灯」的不一致。
7. `client.js`：更新示例与打分说明，新增「不算风险」提示。
8. `README.md`：补充「虚拟商品的售假判定口径」。

## 八、后续建议

1. **把「售假」与「侵权」分开建模**：售假看真伪与授权，侵权看内容来源；不要用同一组词。
2. **继续清理平台稽查词**：`电影/电视剧/影视/代写/范文/工作总结` 等并非都违规，后续可按「商品类型」与「引流话术」再细分。
3. **给词条增加「适用平台」字段**：同一词在闲鱼、小红书、淘宝的含义不同，避免再做跨平台复制。
4. **模型复核加入证据要求**：涉及售假时要求模型说明「冒充了哪个品牌/官方」「盗版了哪件作品」，不能只写「出现网盘链接」。
